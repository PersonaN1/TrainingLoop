# 0001. История тренировок хранится строками, а не JSON-снимком

Дата: 2026-10-16. Статус: принято.

## Контекст

В SetLoop запись истории — одна строка SwiftData с JSON-снимком шагов. Это просто и хорошо синхронизируется, но содержимое JSON нельзя запросить базой. В TrainingLoop главная функция — статистика по упражнению за период (графики, рекорды, «прошлый раз»), то есть запросы «все подходы упражнения X, отсортированные по дате» по истории до 3000 тренировок (~60 тыс. подходов).

## Решение

`Workout` → `WorkoutEntry` → `WorkoutSet` — отдельные сущности SwiftData. У `WorkoutSet` денормализованы `exerciseID` и `workoutStartedAt`, чтобы статистика упражнения бралась одним запросом с предикатом. Шаблон, наоборот, остаётся одним JSON (`definitionData`): по нему ничего не ищут, и он редактируется и синхронизируется целиком.

## Альтернативы

- **JSON-снимок, как в SetLoop**: для любого графика пришлось бы читать и декодировать всю историю. Отклонено из-за производительности и сложности кеширования.
- **JSON + отдельная таблица-индекс подходов**: две копии одних данных, которые надо держать в согласии. Отклонено.

## Последствия

- Больше сущностей и связей; при синхронизации CloudKit (v1.1) тренировка приходит частями — экраны должны переживать неполную тренировку.
- Денормализованные поля нужно обновлять при правке тренировки задним числом (смена даты).
- Смена модели после релиза требует миграции; поэтому схема версионируется с первого релиза.
